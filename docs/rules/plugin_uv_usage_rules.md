# uv 利用ルール

Python script の実行と依存の管理を uv で行うときのルール。版番号の選定と記入を uv に任せ、人と AI が版番号を手で書かずに済むようにする。

---

## 適用範囲

- 本文書は、プロジェクトの指示（CLAUDE.md・利用者の指示等）が uv の利用を定めているときに適用する。指示が無いプロジェクトに適用を強いない
- 指示が無いプロジェクトでも、script が標準ライブラリ以外に依存するときは、本文書の採否を検討する。依存を足すこと自体は、[plugin_implementation_guidelines.md](plugin_implementation_guidelines.md) のとおり利用者の許諾を要する
- 配布する script に適用すると、利用者の環境に uv の導入を求める。配布物に適用するかは、利用者環境への要求として判断する
- 標準ライブラリだけの script は、依存の管理が要らない。実行を `uv run` に揃えるかは、プロジェクトの指示に従う

---

## 依存の宣言の置き場

| 対象                                                 | 宣言の置き場                               |
| ---------------------------------------------------- | ------------------------------------------ |
| 単独で完結する script、および配布する script         | script ごとの PEP 723 インラインメタデータ |
| 共有モジュールやテストを持つ、複数 script のまとまり | プロジェクトルートの `pyproject.toml`      |

- PEP 723 の宣言は、実行する入口の script だけが読む。共有モジュールにメタデータを書いても読まれない。共有モジュールの依存を script ごとに宣言すると、重複と宣言漏れが起きる。そのため、まとまりのある開発用の script とテストは `pyproject.toml` に置く
- 配布する script は、利用者の環境にプロジェクトのルートが無いため、`pyproject.toml` を使えない。共有モジュールの依存は、それを import するすべての入口 script に宣言する
- `pyproject.toml` を使うときは、配布しないプロジェクトとして `[tool.uv]` に `package = false` を書く。テストだけが使う依存は、`uv add --dev` で `dev` グループに入れる
- `pyproject.toml` を使うときは、仮想環境 `.venv` ができる。`.gitignore` に加える

以降の節のコマンドは、PEP 723 の場合（`--script <script>` を付ける）で書く。`pyproject.toml` の場合は、`--script <script>` を外して読み替える。違いは次の 2 点である。

- `uv add` と `uv remove` は、ロックまで自動で更新する。別に `uv lock` を実行しなくてよい
- テストは `uv run --locked python -m unittest ...` で実行する

---

## 実行 [MANDATORY]

- Python script は `uv run` で実行する。システムの `python3` で直接実行しない
- 依存と Python の版は、script ごとに PEP 723 のインラインメタデータで宣言する。`uv run` は宣言を満たす Python と依存を用意してから実行する
- 公開直後の版を取り込まない設定（後述）も、同じメタデータの `[tool.uv]` に書く。コマンドのオプションにすると、ロック・実行・更新のどれかで付け忘れ、`uv run --locked` が失敗する

```python
# /// script
# requires-python = ">=3.15"
# dependencies = ["foo>=1.2.0"]
#
# [tool.uv]
# exclude-newer = "3 days"
# ///
```

---

## 依存の追加と削除 [MANDATORY]

- 依存を加える前に、利用者の許諾を得る（[plugin_implementation_guidelines.md](plugin_implementation_guidelines.md)）
- 依存は `uv add --script <script> --bounds lower <package>` で加える。uv が解決した版を下限として宣言に書き込む
- 依存は `uv remove --script <script> <package>` で外す
- 版番号を手で書かない。手で書くと、書き手が知っている古い版が下限になる
- 下限が決めるのは、解決の候補になる版の範囲だけである。実行される版はロックファイルが決める

---

## ロック

- `uv lock --script <script>` で、解決した版をロックファイルに固定する。`uv add --script` はロックを作らないため、追加のあとに実行する
- ロックファイルは script と一緒に commit する。ロックファイルは版だけでなく、配布ファイルのハッシュも固定する
- `uv run --locked` で、ロックファイルが宣言と食い違っていないことを確かめて実行する。`--locked` を付けなくても、ロックがあれば `uv run` はその版を使う。`--locked` の役目は、食い違いを検出して失敗させることである。ロックの無い script は、実行する環境で依存が解決され、固定されない
- script のロックが食い違ったときも、エラーには `uv.lock` と表示される

---

## 更新

- 古くなった依存は `uv tree --script <script> --outdated` で確かめる
- 更新は `uv lock --script <script> --upgrade`（全部）または `--upgrade-package <package>`（個別）で行う
- 更新したらロックファイルの差分を読み、版が上がった依存と、新しく入った依存を確かめてから commit する

---

## 公開直後の版を取り込まない

乗っ取られたパッケージの新しい版に不正なコードを仕込む攻撃では、公開から発覚・取り下げまでの間に取り込んだ利用者が被害を受ける。

- script のメタデータに `[tool.uv]` の `exclude-newer = "3 days"` を宣言し、公開から 3 日未満の版を候補から外す。追加・ロック・更新・実行のすべてに同じ設定が効く
- 3 日は、このプロジェクト群の方針として定めた値である。短すぎると発覚前の版を取り込み、長すぎると脆弱性の修正版の取り込みが遅れる
- 脆弱性の修正版を急いで取り込むときは、メタデータに `exclude-newer-package = { <package> = "<日時>" }` を足して、そのパッケージだけ基準の日時を遅らせる。その版の変更内容と公開元を確かめてから使い、取り込んだら例外を消す
- この待ち期間で防げるのは、公開後すぐに発覚する攻撃だけである。長期間気づかれない攻撃は防げない

---

## Python の版

- `requires-python` の下限は、最新の安定版に合わせる。古い版は修正の提供が終わり、セキュリティ上の懸念が残るため、新しい版を強制する。手元に無ければ uv がダウンロードする
- 利用できる版は `uv python list` で確かめる。一覧の先頭は alpha・beta・rc の版のことがあるため、これらを除いた最新を選ぶ
