# script のエラー出力

Claude Code プラグインの Python script が、終了コードとエラーをどう返すかの規範。出力を読むのは主に AI であり、自然文から失敗の種類を読み取って分岐できる。本文書は AI が読む機械可読な出力を対象とし、人間が読む表示形式は対象外とする。

> [!IMPORTANT]
> **適用者注意**
>
> 既存の script は、本ルールに適合しないことだけを理由に違反として扱わない。適用するのは**新しく配置する** script であり、既存の script は改修の機会に寄せる。
>
> 本ブロックはルールの内容ではなく、このルールをどの対象へ適用するかを適用者へ指示するものである。ルール本体と並べて矛盾を論じてはならない。

## 終了コード [MANDATORY]

| 値       | 意味                                                 | 意味を定める場所         |
| -------- | ---------------------------------------------------- | ------------------------ |
| `0`      | 依頼された操作が完了した                             | 本文書（全 script 共通） |
| `1`      | 完了しなかった。区別のないエラーで、理由の区別は無い | 本文書（全 script 共通） |
| `2`      | 引数を受理できなかった（`argparse` が自ら返す値）    | 本文書（全 script 共通） |
| `3` 以上 | 完了しなかった。理由はその値ごとに異なる             | それを返した script だけ |

全 script に共通の意味を持つのは `0` / `1` / `2` の 3 つだけである。これらに固有の理由を割り当ててはならない。理由を区別する script は、その理由へ `3` 以降を割り当てる。

`2` を予約するのは、`argparse` が引数エラーで自ら `sys.exit(2)` を呼ぶためである。予約しなければ、`argparse` を使うだけで宣言の無い値が外へ出る。これを上書きして畳ませる形は、全 script に定型コードを強い、書き忘れが黙って違反になる。

- `1` を見たら、それ以上の区別は無い。`2` を見たら、引数の渡し方が誤っている。`3` 以上を見たら、それを返した script に意味の宣言がある
- **「完了した」の判定に、結果の中身を混ぜない**。検査して所見が 0 件でも、変更が要らなくても、対象が 0 件でも、依頼された操作そのものは完了している。いずれも `0` で返し、内容は標準出力の JSON で示す
- **`3` 以上の値の意味を、それを返した script 以外の記述から推論してはならない**

### `3` 以上に共通の意味を置かない理由

エラーの契約は、その script 自身が持つ。呼び出し側が持つと、別の場面から呼んだときに参照先が無い。原因の種類ごとに数値を割り当てる体系を中央に置くと、その体系を管理し続けるコストが割に合わない。

その代わり、`3` 以上の値の意味は、それを返した script の中に書き、読めば分かる状態にする。定義がどこにも無いと、読み手は他の script の実装から規約を推測するしかなく、存在しない規約が生まれる。

## 終了コードの宣言 [MANDATORY]

- `3` 以上の値を返す script は、自身の module docstring に、返しうる全終了コードの完全な表を置く。表には `0` も含める
- 宣言を持たない script は `0` / `1` / `2` しか返さない
- 他の script の終了コードを透過するラッパーにも、同じ義務が及ぶ。透過する値域を自身の docstring に宣言するか、宣言しないなら `0` / `1` / `2` に畳む
- 設計書が既に終了コードの契約を定めている領域では、その設計書が当該領域の正本である。その領域へ script を足すときは設計書に従い、同じ表を自身の docstring にも宣言する

```python
"""Foo を Bar へ変換する。

## 終了コード

| code | 意味                             |
| ---- | -------------------------------- |
| 0    | 変換が完了した                   |
| 1    | 区別のないエラー                 |
| 2    | 引数を受理できない（`argparse`） |
| 3    | 変換元を読めない                 |
| 4    | 変換結果を書き込めない           |
"""
```

`3` 以上の数値の選び方は script が決めてよい。連番でも飛ばしても、意味は表だけが与える。値の並びや間隔に分類を読み込ませない（`10` 番台・`20` 番台のような区分は、中央の体系があるという誤解を生む）。

## 呼び出し側 [MANDATORY]

- 値で分岐してよいのは、**産出側の docstring がその値を宣言している場合に限る**
- 宣言が無い場合と、`1` を受けた場合は、理由を区別せず、区別のないエラーとして扱い、エラーの内容を報告する
- 呼び出し側の文書（SKILL.md 等）に書くのは、宣言された値に対する**行動**である。値の**意味**を呼び出し側で定義しない

## 標準出力

- `0` のとき: 結果の JSON
- 非 0 のとき: エラーの JSON

ただし `2` は例外である。`argparse` は自ら usage を標準エラー出力へ書いて終了するため、標準出力に何も残らない。JSON を出させるには `parser.error` の上書きが要り、`2` を予約した理由を失う。

エラーの JSON は `errors` を持つ。

- 値は常に配列とする。1 件でも配列にする。単数と配列が混在すると、受け取る側が形状で分岐する必要が生じる
- 要素は自然文とする。機械可読なコード体系を導入しない

```json
{ "errors": ["入力を受理できない: 期待する形式は {形式}"] }
```

## 標準エラー出力

診断情報を標準エラー出力へ加えてよい。ただし**エラーの内容は標準出力の JSON に必ず含める**。標準エラー出力だけに置くと、標準出力を読む呼び出し側が失敗の理由を得られない。

## 例外

ハーネスが入出力の契約を定める script（Claude Code の hook として起動されるもの等）は、その契約に従う。終了コードの意味や標準出力の形式をハーネスが指定している場合、本文書の規定は適用しない。
