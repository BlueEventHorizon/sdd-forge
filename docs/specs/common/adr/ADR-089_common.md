# ADR-089 common の決定記録

## 1. 継承型 SKILL の責務宣言の規範を、現在問題が起きていなくても残す

### 1.1 コンテキスト

fork 型 SKILL は、Claude Code の公式の不具合のうち修正されていないもの（`$ARGUMENTS` が置換されない、出力が Desktop の UI に届かない、など）があるため、採用していない。したがって、すべての SKILL は継承型で、親の context を引き継ぐ。

継承型 SKILL は、SKILL から SKILL を呼んでも、context の隔離を得られない。fork 境界による隔離が無い代わりに、SKILL 自身が「ここまでしか行わない」と宣言し、親の会話に残る別の作業（実装・PR 作成・Issue 更新など）を引き受けないようにする。
「現在問題が起きていないなら、この規範を削除してよいのではないか」という提案は、今後も出うる。

### 1.2 決定

継承型 SKILL の冒頭に責務宣言（このスキルが行うことを限り、親が依頼している他の作業を引き継がない旨）を書く規範を、残す。削除しない。

決め手は、継承型 SKILL には fork 境界による隔離が無く、宣言が、親の会話に残る別の作業を引き受けないための代わりの防御であること。その前提（fork 型 SKILL を採らないこと）はいまも続いており、問題が起きていないことは、宣言が要らない根拠にならない。

適用範囲は、すべての継承型 SKILL とする。他の SKILL から起動されるものに限らない。

### 1.3 検討した代替案

| 代替案                                               | 棄却理由                                                                                                                                                                                                                                                                                 |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 現在問題が起きていないことを理由に、規範ごと削除する | 問題が起きていないことは、宣言が効いているからか、そもそも危険が無いからかを見分けられない。前提（fork 型 SKILL を採らないため隔離が無いこと）は、いまも続いている。宣言は各 SKILL に 1 行である。削除する場合は、規範・設計書・テスト・各スキルの文言を、整合を取りながら消す作業が要る |
| 対象を、他の SKILL から起動される SKILL に限る       | 継承は、起動経路（利用者の直接起動か、他の SKILL か）によらず発生する。                                                                                                                                                                                                                  |

## 2. 公開直後の版を取り込まない設定を、コマンドのオプションではなくメタデータに宣言する

### 2.1 コンテキスト

uv には、公開から一定期間内の版を解決の候補から外す設定（`exclude-newer`）がある。この設定は、コマンド（依存の追加・ロック・ロックの更新）に `--exclude-newer` を付けても、script の PEP 723 メタデータや `pyproject.toml` の `[tool.uv]` に宣言しても与えられる。「宣言を増やさず、必要なコマンドにオプションを付ければよい」という提案は、今後も出うる。

以下の挙動は uv 0.13.5（macOS）で実験して確かめた。他の版での挙動は確かめていない。

### 2.2 決定

この設定は、コマンドのオプションではなく、script の PEP 723 メタデータの `[tool.uv]`、または `pyproject.toml` の `[tool.uv]` に宣言する。

決め手は、メタデータに宣言すると、ロックと `uv run --locked` が、フラグを付けなくても整合すること。特定のパッケージだけ基準の日時を遅らせる設定（`exclude-newer-package`）も、メタデータ（script）と `pyproject.toml` のどちらに宣言しても、ロックと `uv run --locked` が通った。

### 2.3 検討した代替案

| 代替案                                                                                  | 棄却理由                                                                                                                                                                                                                                                                                                                                                                                           |
| --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| コマンド（`uv add` / `uv lock` / `uv lock --upgrade`）に `--exclude-newer` を付ける運用 | ロックに `exclude-newer` が記録される（相対指定は `exclude-newer-span = "P3D"` の形）。その後に同じ指定なしで `uv run --locked` を実行すると、「lockfile needs to be updated」で失敗する。急ぎの修正版の例外にする `--exclude-newer-package` でも同じ失敗が起きる。環境変数 `UV_EXCLUDE_NEWER` を付ければ通るが、付け忘れを防ぐ手段が人と AI の注意だけになる。前提は uv 0.13.5 での実験結果である |

### 2.4 影響
