# 新規作成の手順

consult を、新規作成（文書をゼロから作る対話）で使うときの扱いを定める。壁打ち・ディスカッション・たたき台の作成、要件定義書を新しく作る対話がこれにあたる。consult の SKILL は用途に依らない対話の方法だけを持ち、この用途に固有の扱いは本書が持つ。

## 1. 入力と完成物

入力は会話の文脈（会話の流れ、渡された文書・コード）にある。consult は文脈から論点を取り出す。完成物は文書である。

## 2. 決まったことの扱い

- 論点ごとには反映しない。文書は、利用者の指示を受けてから、対話の内容をもとに書く（書き直す）
- 決着を求めない。各論点では、決めること・要旨・AI の見解（推奨案）を述べ、利用者の応答を受ける。利用者の思考に付き合い、判断を求める問い（「これで進めてよいですか」を含む）を発しない
- 述べ終えて利用者が応答した論点は、状態を「議論済み」とし、結果の列に議論で分かったことを 1 句で書く。次の論点へは、利用者の指示で進む
- 利用者が「決めたい」「これで確定」と明示したときだけ、その論点を「決着」とする
- たたき台を書いたら、そこで止まる。列挙した論点を、続けて問わない

## 3. 表示

コンソールと HTML の役割、一覧の形、いまの論点の書き方、位置の書き方は、対話による修正と同じである（`dialogue_revision_handling.md` の 2〜3 節。SKILL が示す、同じディレクトリの文書）。状態に「議論済み」を加える。

## 4. 論点が 1 つのとき

一覧を出さない。決めること・要旨・AI の見解・位置を述べ、利用者の応答を受ける。

## 5. 提示状態の置き場

表示の材料が提示状態の置き場になる。HTML を作る script ができるまでは、会話コンテキストに持ち、再掲した最新の一覧を現在の提示状態とする。

## 6. 記録

新規作成では、consult brief を記録しない。記録の識別子と置き場が未確定のためである。

## 7. 終了と結果

- 利用者の指示で、一覧の内容から文書を書く。書いた文書が結果である
- 書く前に、文書に入れる内容（決着・議論済みの論点）と入れないもの（保留・対象外・取り下げ）を一覧で示す
