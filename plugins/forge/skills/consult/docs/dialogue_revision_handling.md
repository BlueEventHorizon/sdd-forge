# 対話による修正の手順

consult を、対話による修正（対話の中で決まったことを、その都度その場で反映していく対話）で使うときの扱いを定める。報告・質問への回答だけの対話も、この用途に含める。consult の SKILL は用途に依らない対話の方法だけを持ち、この用途に固有の扱いは本書が持つ。

## 1. 入力

対話による修正には、review の評価のような入力のファイルが無い。入力は会話の文脈（会話の流れ、渡された文書・コード）にある。consult は文脈から論点を取り出す。

## 2. 表示の手段

表示は、利用者に分かりやすく説明するための手段である。コンソールと HTML を役割で分ける。

| 媒体       | 載せるもの                                                                 | 理由                                               |
| ---------- | -------------------------------------------------------------------------- | -------------------------------------------------- |
| コンソール | 概観。一覧、いまの論点、そこで決めること、推奨案の一文。進むたびに再掲する | 機能が限られ、流れて消える。毎回出し直す概観に向く |
| HTML       | 詳細。要旨・根拠・確信度・リンク付きの位置・選択肢                         | リンクを含む詳しい情報を整然と示せる               |

HTML は、consult が文脈から取り出した表示の材料を script に渡し、script が検査して作る。AI は HTML を直接書かない。

**HTML を作る script は、まだ無い**（設計が未確定）。それまでは、詳細もコンソールに述べる。そのときも 3 節の書き方を守る。

## 3. コンソールの書き方

### 3.1 一覧

```markdown
**一覧**（全 {N} 件・決着 {k} 件・残り {r} 件／現在 #{n}）
変更: {前回の一覧から変わったことを 1 行で}

| #   | 論点       | 状態         | 結果         | 課題・待っているもの    |
| --- | ---------- | ------------ | ------------ | ----------------------- |
| 1   | {短い名前} | 決着（更新） | {採否と理由} | —                       |
| ▶ 2 | {短い名前} | 進行中       | —            | {何が解決していないか}  |
| 3   | {短い名前} | 未着手       | —            | {#2 の結論を待つ、など} |
```

- 重要度の列は持たない。この用途には、根拠を持って重要度を付ける上流が無い
- 番号は、他の論点の前提になるものから振る。`課題・待っているもの` に、その論点が何を待っているかを書く
- いま扱っている行は `#` に `▶` を付ける。前回から変わった行は状態の後ろに `（更新）`、新しく加えた行は `（新規）` を付ける。最初の一覧には付けない
- `変更` は最初の一覧では書かない
- 各欄は 1 句に収める。ファイルのパスは一覧に入れない

### 3.2 いまの論点

いまの論点は、表にせず、次の形で書く。一覧と見分けられるよう、上下にセパレータライン（`---`）を入れる。

```markdown
---

**▶ #{n}　{短い名前}**

- **決めること**: {利用者が何を判断するのかを 1 行で}
- **要旨**: {consult brief の要旨}
- **推奨案**: {consult brief の推奨案}
- **位置**:
  - `{path}:{行}`
    - 書いてあること: {その行の内容を 1 行で}

---
```

位置は、**表に入れず、箇条書きで書く**。表の中のパスはクリックして開けない。各位置は、リポジトリのルートからのパスと行を `path/to/file.md:行` の形で書き、その下に何が書いてあるかを添える。文書 ID と行番号だけ（`REQ-017:20` など）では、パスでないので開けない。

### 3.3 その他

- 並列する項目は表にまとめる。ただしパスを含む項目は箇条書きにする
- 章立てを細分化しない
- 一覧のほかに表・コード片を並べない。使うなら 1 つまで

## 4. 論点が 1 つのとき

一覧を出さない。決めること・要旨・推奨案・位置を 3.2 の形で述べ、利用者の応答を受ける。報告や回答のように決めることが無いときは、要旨と位置だけを述べる。

## 5. 提示状態の置き場

表示の材料が提示状態の置き場になる。HTML を作る script ができるまでは、会話コンテキストに持ち、再掲した最新の一覧を現在の提示状態とする。

## 6. 記録

対話による修正では、consult brief を記録しない。記録の識別子と置き場が未確定のためである。

## 7. 実行と結果

- 利用者が決めた論点は、その場で実行してよい。決めていない論点は実行しない
- 終えるときは、最終の一覧を再掲し、それを利用者への結果とする
